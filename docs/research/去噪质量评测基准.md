# 去噪质量评测基准：构念定义、标注规范与方法论

> 本文档是 `eval/` 评测工具包的理论依据，基于对"AI 个性化信息策展系统"评测学的系统调研。
> 目的：把"这条内容选得对不对"从主观直觉，转化为**可标注、可度量、可回归**的工程标尺。

---

## 1. 为什么要建这个基准

此类系统的价值主张是"用时间压缩对抗信息过载"（替你读完互联网）。但它踩在一个根本张力上：
**它存在的理由是减少过载，自身却可能成为新的过载/打断源。** Reuters Digital News Report 2025
显示全球已有 **40% 用户主动回避新闻**（2017 年仅 29%），主因是不间断信息流带来的心理疲劳
（Song et al. 2017：过载 → 疲劳 + 分析瘫痪 → 回避）。

同时，推荐/策展系统研究长期"重准确率、轻度量"——多数工作只用离线准确率，而准确率与真实用户
满意度并不等同（swissinfo.ch 实证：离线最优的"推最热门"在线上失效）。**项目普遍缺少质量标尺，
这正是本基准要补的空白。**

## 2. 评测分三层（不能混为一谈）

| 层 | 系统动作 | 核心问题 | 指标家族 |
|---|---|---|---|
| ① 去噪/筛选 | `feeds.score_item` + 关键词覆盖选 top_k | 选进来的该不该选？漏没漏？ | precision@k / recall / 误推率 |
| ② 排序 | `combined_score`（规则 0.4 + AI 0.6） | 排第一的是不是最好？够不够多样/新颖？ | nDCG@k / MRR / ILD 多样性 / 新颖性 / 覆盖度 |
| ③ 摘要/理由 | `RssAnalyzer` / `Summarizer` | 摘要忠不忠实、有没有信息量？ | G-Eval 四维（忠实/相关/连贯/流畅） |

**关键警示**（Kaminskas & Bridge 超越准确性综述）：多样性、新颖性、惊喜度、覆盖度彼此相关，
**优化一个会牵动其他**。因此基准必须多维同时测，否则会出现"准确率涨了、多样性崩了"的隐性退化。

---

## 3. "值得读"如何操作化（基准的地基）

"这条值不值得推送"不是一个模糊直觉，文献给了可标注的构念。三个来源相互印证：

- **新闻价值理论**：Galtung & Ruge (1965) 的 12 因子 → Harcup & O'Neill (2001/2015) 的更新版，
  明确把 **"可分享性 (shareability)"** 纳入现代新闻价值——"让你笑或让你怒的内容"。
- **传播心理学**（Berger & Milkman, *JMR* 2012，NYT 全量数据 + 因果实验）：内容是否被转发，由
  **生理唤醒度 (arousal)** 驱动——高唤醒的敬畏/愤怒/焦虑更易传播，低唤醒的悲伤抑制传播；
  且 **实用价值、惊奇度、正向效价** 都独立正向预测传播，控制外部曝光后仍成立。
- **推荐系统**：相关性 (relevance) + 新颖性 (novelty) + 惊喜度 (serendipity)。

**受众校准（反直觉但重要）**：Berger 后续研究（*J Marketing* 2019）发现，信息密集型内容在
*一般* 场景反而抑制分享，但在 **"高风险/决策相关"场景有效**。技术情报正是决策相关场景，
因此本基准对技术受众**上调"实用价值 (usefulness)"权重**——这是"受众校准"的由来。

## 4. 标注规范（Gold Set schema）

对每条候选独立标注以下 6 个字段（程序化定义见 `eval/schema.py` 的 `GOLD_FIELDS`）：

| 字段 | 类型 | 锚点定义 | 依据 |
|---|---|---|---|
| `worth_pushing` | bool（**主标签**） | 是否愿意转发到同事/同行群 | TLDR 群聊测试 / Harcup shareability |
| `relevance` | 0–2 | 0 无关 / 1 边缘 / 2 强相关（对 agent·llm·mcp·ai 画像） | 推荐相关性 |
| `usefulness` | 0–2 | 0 无 / 1 一般 / 2 高（对该方向的实际决策/工作） | Berger 实用价值（技术受众加权） |
| `novelty_surprise` | 0–2 | 0 已知 / 1 略有新意 / 2 明显新知 | 超越准确性 / Berger surprise |
| `summary_faithful` | bool | 摘要是否忠实正文、无臆造 | G-Eval consistency |
| `summary_informative` | 0–2 | 0 空泛 / 1 一般 / 2 抓到要点 | G-Eval relevance/completeness |

**标注协议要点**（RoSE, ACL 2023）：
- 用**细粒度可判定单元**（Atomic Content Units 思路）而非整体印象分，能显著提高评分者一致性。
- **对齐原则**：参考型指标用参考型人工评测验证；摘要忠实性必须以"源文 vs 摘要"无参考方式判，
  解耦"参考摘要质量"的干扰。
- **一致性门槛**：Cohen's κ / Krippendorff's α ≥ 0.7 良好，0.6–0.7 可用，< 0.6 说明构念定义
  不清，**先改标注规范再扩标**（用 `eval/agreement.py` 校验）。

## 5. 自动评测（LLM-as-judge）：能用，但有硬边界

- **有效性**：G-Eval（CoT + 打分）在新闻域与人类 Spearman 相关约 0.5，远高于 ROUGE（0.16–0.33）；
  可作规模化打分器。
- **必须防的偏差**（实证排序，CALM/多项研究）：
  1. **格式/风格偏差效应量 0.76–0.92，约为位置偏差（≤0.04）的 20 倍**——评判器偏爱 Markdown 排版。
     **对本项目是直接警示**：用 LLM 给自己生成的 Markdown 摘要打分，测的是"谁排版漂亮"而非质量，
     **判分前必须剥离格式**。
  2. 自我偏好偏差（偏爱与自己同族模型的输出）→ 评判器与分析器尽量不同族。
  3. 冗长偏差（偏爱更长回答）。
- **最佳实践**（arXiv 2506.13639 实证 + 工业界 playbook）：
  1. 同时提供**参考标准 + 锚点分数描述**（只给最高/最低分描述即可，缺一项显著掉对齐度）；
  2. **采样多次取均值**，优于 greedy 单次；
  3. **二元/分类判定优于 Likert**；
  4. 成对比较做**顺序翻转 (response-flipping)**；
  5. 判分前**剥离 Markdown**；
  6. 上信前先用人工金标算 **κ / α**（Databricks 公开值 α≈0.57–0.70、κ≈0.64–0.65 为现实参照）。
- **能力边界**（Findings EMNLP 2023）：LLM 评判器**区分不了质量接近的候选**、对候选/维度敏感、
  质量越高越不可靠。→ 基准必须含**难负例**（见 §7），否则测不出迭代差异。

## 6. 指标体系细则

- **去噪层**：`precision@k`（入选 k 条中几条金标正向）、`recall`（候选池中金标正向被选中比例）、
  `F1`、**误推率**（推了但 `worth_pushing=false`）。
- **排序层**：`nDCG@k`、`MRR`（对 `relevance`）；超越准确性——**Intra-List Diversity (ILD)**
  （入选条目两两不相似度）、兴趣覆盖度、新颖性（逆热度）。
- **摘要层**：G-Eval 四维，忠实性用源文无参考判定。
- **多指标同时报**：避免单指标优化导致的隐性退化（§2）。

---

## 7. 离线评测的三个陷阱（决定基准可信度）

1. **离线 ≠ 在线**（swissinfo.ch）：离线指标赢了不等于线上好。→ 必须留小的行为/在线校验回路
   （IM 👍/👎 反馈）。
2. **伪相关**（Findings EMNLP 2023）：多质量维度高度相关会制造虚假的指标-人类相关。→ 维度尽量正交。
3. **区分力问题**：指标只在质量差距大时排序正确，分数接近时相关性≈0。→ 基准采样必须纳入
   **近邻难负例**（分数接近但入选/落选不同的对）。`eval/sample_for_annotation.py` 已内置该策略。

## 8. 数据来源说明

- **本项目金标必须自建**：MIND（英文，1M 用户/16 万篇）、Adressa（挪威语）是方法论参照与
  （若做模型层实验）预训练资源，**不能直接迁移为中文技术情报的金标**。
- 本基准的候选池来自系统自身落盘：`reports/{date}/eval_candidates.json`（开 eval_dump，含 GitHub
  全量打分项目 + 各 RSS/微信频道的**规则阶段完整候选池**——其中进入 LLM 初筛的条目带 AI 打分、
  入选条目带 `pick_rank`、落选条目即近邻负例，因此可同时评估筛选阶段的 recall 与"漏选"）与
  `data/history/{date}.json`（GitHub 全量打分池，每次运行都落盘）。
- **未充分覆盖**：中文 LLM 评判器在中文摘要上的偏差特征缺专门证据（现有偏差研究多为英文），
  落地 Phase 3 时需本地实测。
